# FORMULOVE — Telegram-магазин

Каталог, кошик, оформлення замовлень і панель власника. Cloudflare Workers + D1. Після налаштування Workers Builds зміни гілки `main` автоматично розгортаються у Cloudflare. Копіювати код у мобільний редактор не потрібно.

**Для ввімкнення реальних передзамовлень: [коротка інструкція](ACTIVATE_PREORDERS_UA.md).** Початкове встановлення: [INSTALL_UA.md](INSTALL_UA.md).

## Що вже є

- 9 чернеткових товарів: футболки, кепка, світшот, худі, зіпка без флісу, парні футболки та світшоти.
- Розміри, кольори, незалежні розміри в парах; кошик і подарункове пакування.
- Оформлення, Нова пошта/поштомат, погоджувана післяплата або переказ.
- Замовлення, статуси, скасування, залишки, ТТН, CSV для власника.
- Вебпанель `/setup`; фото можна завантажувати через Telegram.
- Постійна D1-база, захист webhook, перевірка повторних запитів і черга сповіщень.

## Встановлення

Для нового Worker також є [майстер Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https%3A%2F%2Fgithub.com%2Fhubaluna%2FBotLuna). Він може створити копію репозиторію. Якщо Worker вже є, підключіть до нього саме цей репозиторій за інструкцією, щоб не створювати дубль.

У Cloudflare виберіть цей репозиторій, гілку `main`, назву Worker **formulove-bot**. Build command: `npm run build`. Deploy command: `npx wrangler deploy`. Шлях: корінь репозиторію.

У `wrangler.jsonc` уже є binding `DB`, база `formulove-db` та Cron `*/5 * * * *`. Wrangler підтримує створення D1 без ручного ID. Якщо в акаунті вже є база з реальними замовленнями, спочатку звірте binding та ID; не створюйте другу базу замість чинної.

Потрібні секрети Worker: `BOT_TOKEN`, `SETUP_KEY` (від 32 символів), потім `ADMIN_IDS`. Токени не додавайте у GitHub, Issues або чат. Реєстрація webhook виконується власником із `/setup` після додавання секретів.

## Перевірки

Node 22.13+ або 24:

```sh
npm install
npm run build
npm run check
npm test
```

63 тести використовують справжній SQLite через адаптер D1: галерея, навігація, кошик, дублювання запитів, ціни, залишки, оформлення, доступи, секрети й повторні сповіщення. Локальні тести не замінюють перевірку реального Cloudflare і Telegram.

`src/entry.js` — точка входу; `src/` — робочі модулі; `build.mjs` готує HTML панелі. `worker.js` для ручного встановлення збережено у попередньому архіві; цей репозиторій розгортає модулі `src/`. `catalog.json` та `store.json` — початкові чернетки; після ініціалізації чинні налаштування зберігаються в D1.

## Межі та дані

Початково ввімкнено **demo**. Ціни, фото, заміри й умови потрібно підтвердити до реальних продажів. Доставка оплачується й опрацьовується за вашими умовами; інтеграції еквайрингу, API Нової пошти та фіскалізації немає. Позначення оплати — ручне, не автоматична перевірка банку. У парних комплектів окремі залишки, без спільного складу компонентів.

Замовлення містять персональні дані. Вони не публікуються в GitHub. Задайте справжні умови зберігання й видалення даних. Резервні копії бази робіть у Cloudflare D1. Ініціалізація не стирає чинні записи.

Публікація цього коду не означає, що Worker уже розгорнутий або Telegram підключений. Повні попередні архіви й оригінальні зображення збережені окремо в робочому просторі; цей репозиторій містить код та інструкцію для встановлення.

Офіційна документація: [Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/), [автоматичне створення D1](https://developers.cloudflare.com/changelog/post/2025-10-24-automatic-resource-provisioning/), [Secrets](https://developers.cloudflare.com/workers/configuration/secrets/).


## Зображення футболок

Кнопка «Показати все» або команда /all відкриває альбом усіх дев’яти моделей. Під альбомом — пронумеровані кнопки вибору товару. У підписах — назва та ціна; у парних комплектів зазначено, що ціна за дві речі. За понад десять моделей з’являються наступні сторінки. У категорії є окрема кнопка «Показати фото».

Фото, короткий опис, ціна та вибір варіанта тепер в одній картці. Картка стисло повідомляє «Виготовлення під замовлення», а умови виконання покупець бачить перед підтвердженням. Фото власника з /photo або панелі має пріоритет. Вбудовані концепції дозволені в live тільки для передзамовлень. Для готових товарів збережено вимогу реальних фото й замірів. Зображення, завантажені як файли, надсилаються окремим альбомом документів: Telegram не змішує їх із фотографіями.

Вихідні JPEG зберігаються як Base64 у media-source; npm run build декодує їх у public/products, а Workers Static Assets розміщує готові зображення на тому самому домені. Додатковий платний хостинг для фото не потрібен. Не копіюйте в public секрети або клієнтські дані.

Після успішної збірки відкрийте /products/heart-concept-v1.jpg, /products/lights-concept-v1.jpg або /products/speed-concept-v1.jpg на адресі свого Worker. У Telegram надішліть /start, потім натисніть «Показати все». Якщо автоматична збірка не запустилася, натисніть Retry build у Cloudflare.


## Реальні передзамовлення

Режим live відокремлено від типу продажів: preorder (передзамовлення) або ready (готові товари). У preorder немає вимоги вигадувати заміри чи називати мокап реальним фото. Покупець бачить умови до підтвердження; заявка зберігається як live і надсилається власнику. У самому боті автоматичного списання коштів немає. Погодьте точні характеристики, остаточну ціну, строк і дані продавця до оплати. Знімок умов передзамовлення зберігається разом із замовленням.

Числовий Telegram ID можна зберегти в захищеній панелі. Якщо ADMIN_IDS вже задано в Cloudflare Secrets, він має пріоритет. Введення username замість числового ID не активує live. Нові поля не видаляють попередні замовлення або фото. Контакт @da_martin та назва FORMULOVE підставляються, якщо відповідні поля порожні; це не підтвердження реєстрації ФОП або юридичних реквізитів.


## Тексти для покупця

На головній — одне привітання з меню. Картка товару містить фото й потрібні для вибору відомості; для опису понад ліміт підпису Telegram використовується окреме повідомлення. Допомогу розділено на коротке основне меню й додаткові питання. В оформленні є «Назад» і «Скасувати», а текст згоди містить посилання на повні умови. Меню /admin також розділено на розділи.

Оновлення старих текстів у src/copy.js спрацьовує лише за точного збігу з попередніми типовими формулюваннями. Власні тексти, ціни та фото власника не замінюються; при читанні база не перезаписується. Непідтверджені параметри тканини не подаються як перевірені факти. Картки передзамовлення містять «Виготовлення під замовлення». Перед підтвердженням зазначено, що розмір, матеріали, остаточна вартість і строк погоджуються до оплати. Раніше збережені умови замовлень залишаються в їхньому знімку.

Результати перевірки та приклади текстів: [UX_AUDIT_UA.md](UX_AUDIT_UA.md). Автоматична перевірка: npm run check, npm test. Тести використовують локальну SQLite-базу та імітацію відповідей Telegram і не створюють замовлень у робочому магазині.
