# FORMULOVE: встановлення через GitHub з iPhone

Код уже в цьому репозиторії. Вам не потрібно відкривати worker.js і копіювати його у Cloudflare.

## 1. Підключіть саме репозиторій

Прив'язати акаунт GitHub і підключити репозиторій до Worker — окремі дії.

1. Увійдіть у [Workers & Pages](https://dash.cloudflare.com/?to=/:account/workers-and-pages).
2. Якщо Worker **formulove-bot** вже є, відкрийте його → Settings → Build/Builds → Connect. Підключіть GitHub і виберіть **hubaluna/BotLuna**.
3. Якщо Worker ще немає: Create application → підключення GitHub/Import a repository → **hubaluna/BotLuna**.
4. Назва Worker: **formulove-bot**. Вона має збігатися з `name` у wrangler.jsonc. Якщо вже створено інший Worker, спочатку повідомте його точну назву для виправлення конфігурації.
5. Production branch: **main**. Root directory: корінь `/`.
6. Build command: **npm run build**.
7. Deploy command: **npx wrangler deploy**.
8. Збережіть і запустіть Deploy/Retry build. Дочекайтеся успішного завершення.

Для простого тесту виберіть Workers Free. Не вмикайте платні доповнення. Застосовуються поточні квоти Cloudflare.

## 2. Перевірте базу

Конфігурація запитує D1 binding **DB**. Wrangler може автоматично створити базу **formulove-db**. Після першого успішного розгортання відкрийте Worker → Bindings: там має бути **DB → D1**.

Якщо ресурс не створився через права збірки: відкрийте D1, створіть **formulove-db**, скопіюйте її **Database ID** і додайте `database_id` до цього binding у wrangler.jsonc. Database ID не є паролем. Не публікуйте Cloudflare API token. Альтернатива — додати binding **DB** у Dashboard, але конфігурацію Git також потрібно узгодити, щоб наступний deploy використовував ту саму базу.

Якщо база вже має справжні замовлення, використовуйте її ID. Не видаляйте базу й не скидайте дані заради повторного встановлення.

## 3. Додайте секрети у Worker

Worker → Settings → Variables and Secrets → Add. Тип **Secret**:

- **BOT_TOKEN** — токен вашого бота з BotFather.
- **SETUP_KEY** — окремий випадковий ключ від 32 символів. Збережіть у менеджері паролів. Це пароль панелі власника, не Telegram-токен.

Це runtime-секрети Worker, не лише змінні build. Збережіть/Deploy. Вони не повинні бути у файлах GitHub або в повідомленнях чату. У конфігурації ввімкнено keep_vars, щоб зберігати змінні Dashboard; secrets також залишаються у Cloudflare.

## 4. Підключіть Telegram

1. Відкрийте адресу вашого Worker, яку показує Cloudflare, і додайте **/setup**.
2. Введіть SETUP_KEY.
3. Натисніть **Підготувати базу — перший запуск**.
4. Натисніть **Підключити Telegram**. Якщо бот уже використовує інший webhook, заміну потрібно явно підтвердити. Зупиніть попередню Python-копію, якщо вона працює.
5. Відкрийте свого бота в Telegram → Start → **/id**.
6. Скопіюйте свій числовий Telegram ID. Додайте у Secrets Worker **ADMIN_IDS** із цим числом. Для кількох власників — числа через кому.
7. Збережіть/Deploy, перевірте **/admin**.

## 5. Виконайте тест

Залиште режим **demo**. Нічого не оплачуйте.

- Відкрийте каталог → виберіть товар, колір і розмір.
- Додайте у кошик і змініть кількість.
- Оформіть тестове замовлення; перевірте вартість і пакування.
- Перевірте надходження замовлення власнику, статус і скасування.
- Перевірте пару з двома різними розмірами.

Ціни та початковий асортимент — чернетка. Реальні продажі вмикайте після перевірки товарів, фото, матеріалів, замірів, строків, продавця, оплати, обміну та конфіденційності.

Фото завантажуються власником у Telegram із підписами **/photo heart**, **/asset welcome**, **/asset packaging**. Передавайте як документ, щоб зберегти оригінал. Панель підкаже, які поля ще потрібні для live.

## Типові проблеми

- **No repositories found**: у налаштуваннях GitHub App Cloudflare дозвольте саме BotLuna.
- **Worker name mismatch**: ім'я застосунку Cloudflare й `name` у wrangler.jsonc мають збігатися.
- **Missing entry point**: Root directory має бути коренем цього репозиторію; конфігурація має main src/entry.js.
- **DB binding missing**: перевірте Bindings і лог збірки; потрібен D1 із назвою binding DB.
- **Невірний ключ**: перевірте Secret SETUP_KEY, без випадкових пробілів.
- **Telegram не відповідає**: у /setup запустіть перевірку підключення; перевірте BOT_TOKEN, не публікуючи його.
- **Зміни не з'явилися**: перевірте останню збірку гілки main й лог помилки. Прив'язка GitHub без підключення репозиторію не запускає збірки.

Якщо є помилка, надішліть її текст або скриншот без токенів та персональних даних покупців.
